## Decisions Made
- **httpx over SDK:** muninndb Python SDK installs zero code files on Python 3.14 due to packaging bug. Direct REST calls via httpx (already a dependency) are reliable.
- **Individual writes for batch:** MuninnDB v0.3.6-alpha /api/engrams/batch endpoint ignores the vault field, always writing to default vault. Worked around with sequential individual POST /api/engrams calls that correctly respect the vault parameter.
- **Best-effort dual-write:** MuninnDB write in capture handler is wrapped in try/except after all libSQL/MuninnDB operations complete. Failure logs a warning but never changes the user-facing return value.
- **One-time health check:** get_muninn() checks MuninnDB health once on first call and caches the result. Prevents repeated connection attempts on every tool call when MuninnDB is down.
- **Embedder limitation accepted:** MuninnDB Google embedder failed to initialize (text-embedding-004 not available on v1beta API), resulting in semantic_similarity=0 in ACTIVATE responses. This is a MuninnDB server configuration issue, not a code issue. User approved proceeding -- the integration code is correct and will benefit from embeddings once MuninnDB updates their API version.

## Issues Encountered
- **MuninnDB embedder initialization failure:** text-embedding-004 model not available on v1beta Google API. Results in semantic_similarity=0 for all ACTIVATE responses. This is a MuninnDB server-side configuration issue -- the REST client code sends text correctly, and MuninnDB processes everything else (Hebbian learning, temporal decay, full-text relevance). Will resolve when MuninnDB updates to use the stable v1 API or a different model identifier.
- **32 memories vs 18 expected:** Plan referenced 18 existing memories, but 32 were found in brain.memories at seed time. The extra 14 accumulated from onboarding and usage between planning and execution. All 32 were seeded successfully.
