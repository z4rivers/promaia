<task type="auto">
  <name>Task 2: Extend schema with pgvector extension, HNSW indexes, GIN indexes, and deploy to Supabase</name>
  <files>
    promaia/storage/schema.sql
  </files>
  <action>
    1. Edit `promaia/storage/schema.sql` to add pgvector support at the TOP of the file (before any table definitions):
       ```sql
       -- Enable pgvector for semantic search
       CREATE EXTENSION IF NOT EXISTS vector;
       ```

    2. Add a content_embeddings table (or add embedding column to existing content_items table). The design calls for embeddings alongside content. Add after the content_items table definition:
       ```sql
       -- Content embeddings for semantic search (replaces ChromaDB)
       CREATE TABLE IF NOT EXISTS content_embeddings (
           id SERIAL PRIMARY KEY,
           page_id TEXT NOT NULL,
           chunk_id TEXT,
           content TEXT NOT NULL,
           embedding vector(768) NOT NULL,
           workspace TEXT,
           database_name TEXT,
           metadata JSONB DEFAULT '{}',
           is_chunk BOOLEAN DEFAULT FALSE,
           chunk_index INTEGER,
           total_chunks INTEGER,
           created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
           updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
           UNIQUE(page_id, chunk_id)
       );
       ```
       Use `vector(768)` NOT `halfvec` per Gemini review finding. 768 dims matches gemini-embedding-001 output.

    3. Add a property_embeddings table (replaces ChromaDB property collection):
       ```sql
       CREATE TABLE IF NOT EXISTS property_embeddings (
           id SERIAL PRIMARY KEY,
           page_id TEXT NOT NULL,
           property_name TEXT NOT NULL,
           property_type TEXT,
           property_value TEXT NOT NULL,
           embedding vector(768) NOT NULL,
           workspace TEXT,
           database_name TEXT,
           metadata JSONB DEFAULT '{}',
           created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
           UNIQUE(page_id, property_name)
       );
       ```

    4. Add HNSW indexes on embedding columns (NOT IVFFlat per design decision):
       ```sql
       -- HNSW indexes for fast approximate nearest neighbor search
       CREATE INDEX IF NOT EXISTS idx_content_embeddings_vector
           ON content_embeddings USING hnsw (embedding vector_cosine_ops);
       CREATE INDEX IF NOT EXISTS idx_property_embeddings_vector
           ON property_embeddings USING hnsw (embedding vector_cosine_ops);
       ```
       Use `vector_cosine_ops` because the existing ChromaDB was configured with cosine similarity (`"hnsw:space": "cosine"`).

    5. Add GIN indexes on JSONB metadata columns for hybrid search (keyword + vector):
       ```sql
       -- GIN indexes for hybrid search on metadata
       CREATE INDEX IF NOT EXISTS idx_content_embeddings_metadata
           ON content_embeddings USING gin (metadata);
       CREATE INDEX IF NOT EXISTS idx_property_embeddings_metadata
           ON property_embeddings USING gin (metadata);
       ```

    6. Add additional B-tree indexes for common query patterns:
       ```sql
       CREATE INDEX IF NOT EXISTS idx_content_embeddings_page_id
           ON content_embeddings(page_id);
       CREATE INDEX IF NOT EXISTS idx_content_embeddings_workspace
           ON content_embeddings(workspace);
       CREATE INDEX IF NOT EXISTS idx_property_embeddings_page_id
           ON property_embeddings(page_id);
       CREATE INDEX IF NOT EXISTS idx_property_embeddings_property
           ON property_embeddings(property_name);
       ```

    7. Run the schema against Supabase to verify it deploys cleanly:
       ```
       python -m promaia.storage.db_init init
       ```
       This requires the user's .env to have the Supabase credentials configured. If the connection fails, this will be caught in the checkpoint.
  </action>
