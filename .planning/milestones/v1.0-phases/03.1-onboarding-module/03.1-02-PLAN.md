`run_pc_scan(home_dir=None, db=None) -> dict`:

1. **Git analysis** (already proved):
   - Scan ~/dev/ for .git directories (up to 10 repos)
   - For each repo: `git log --format="%H|%ai|%s" -n 100` to extract commit patterns
   - Derive: chronotype (commits by hour), sprint_duration (burst patterns), active_projects list
   - Store to brain.profile: energy_patterns.chronotype, energy_patterns.peak_focus_hours, context.active_projects

2. **File structure analysis**:
   - Scan ~/dev/ directory names to confirm active projects
   - Check for common config files: .bashrc/.zshrc (shell prefs), package.json/requirements.txt (tech stack)
   - Store to brain.profile: context.tech_stack, context.devices (from OS detection)

3. **Installed apps detection** (Windows-specific):
   - Read registry or use `wmic product get name` (via subprocess) to list installed software
   - Filter for interesting categories: dev tools, productivity, creative, communication
   - Store interesting findings as brain.memories with domain='personal' and source='pc_scan'

4. **Profile updates**:
   - Use direct SQL to upsert into brain.profile (same pattern as _handle_update_profile in mcp_server.py)
   - Each field: source='inferred', confidence=0.6 (inferred from digital artifacts)
   - Generate embeddings for each profile update (use VectorDBManager)

5. **Return value**: dict with {fields_updated: N, repos_scanned: N, apps_found: N, insights: [str]}

Important constraints:
- Use subprocess.run with timeout=30 for all shell commands
- Catch all exceptions per-section so partial results still return
- Use os.path.expanduser('~') if home_dir not provided
- Log to logger (same pattern as engine.py)
- Do NOT import or use the MCP server -- this is a standalone module that brain MCP calls

   - Use existing GmailConnector from promaia.connectors.gmail_connector

   - Use GmailConnector to list threads from last `days_back` days
   - For each thread (up to max_emails): extract sender, recipients, subject, date, snippet
   - Do NOT store raw email content -- only metadata and summaries

3. **Extract profile signals**:
   - **Contacts**: Build frequency map of email contacts (who Zack communicates with most). Store top 10 as brain.profile relationships.people entries
   - **Communication patterns**: Analyze reply timing, email length distribution, formality level. Store as brain.profile communication fields
   - **Topics**: Cluster subjects by keyword to identify recurring themes (work, personal, projects). Store as brain.memories with domain inferred from topic
   - **Activity patterns**: Email send times to augment chronotype data. Store as brain.profile energy_patterns

4. **Profile updates**:
   - Use direct SQL to upsert into brain.profile (same as pc_scan)
   - source='inferred', confidence=0.5 (inferred from email patterns, lower confidence than direct observation)
   - Store contact list as relationships.people value (JSON array of {name, email, frequency, last_contact})

5. **Privacy safeguards**:
   - NEVER store email body text in brain.memories or brain.profile
   - Store ONLY: contact names, frequency counts, subject line keywords, timing patterns
   - All memories stored as summaries: "Communicates frequently with [Name] about [Topic]"

6. **Return value**: dict with {contacts_found: N, emails_scanned: N, fields_updated: N, error: str|None}
