Run all three agents via Gemini, verify output quality against Phase 5 baseline, confirm cost tracking, and get human approval.

Purpose: End-to-end validation that the Gemini migration works -- agents produce useful output, costs are tracked accurately, and budget guards function. This mirrors the Phase 5 Plan 03 validation pattern.

Output: Verified Gemini-powered agent pipeline with cost data.

NOTE on idempotent processing (Success Criterion 2): "Already-processed emails/memories are not re-summarized" is partially addressed by design -- agents query "recent" emails/memories by time window (e.g., last 24 hours for morning briefing, since last run for email-triage). This means re-runs within the same time window may process the same data, but this is acceptable because: (1) agent runs are one-shot (no iterative tool use that could re-process), (2) the scheduler runs each agent at fixed intervals so natural time windows prevent most overlap, and (3) the output is a synthesis/summary, not a side-effect-producing action. True deduplication (tracking last-processed-email-ID) would add complexity without meaningful benefit at 3x/day frequency.
</objective>
