  <name>Task 1: Time-of-day scheduling and direct Telegram push in scheduler</name>
  <files>promaia/agents/scheduler.py</files>
  <action>
Add time-of-day scheduling to AgentScheduler. Three changes:

1. **Add `_next_run_time()` function** (module-level or static method) that calculates the next scheduled run time from an agent's `schedule` list. Each entry is `(day_spec, time_str)` where day_spec is "daily" or a weekday abbreviation ("Mon", "Tue", etc.) and time_str is "HH:MM". All times are in user timezone (`America/New_York` via `zoneinfo.ZoneInfo`). Import `from zoneinfo import ZoneInfo` and `from datetime import time` (already has datetime imported). The function should:
   - Get `now = datetime.now(ZoneInfo("America/New_York"))`
   - For each schedule entry, calculate the next occurrence (today if not yet past, else tomorrow for "daily"; next matching weekday for specific days)
   - Return the minimum candidate datetime

2. **Add `_run_scheduled_agent()` async method** to AgentScheduler that replaces `_run_agent_loop()` for agents with `schedule` set. The loop:
   - Calls `_next_run_time(agent.schedule)` to get next run time
   - Calculates sleep_seconds = `(next_run - datetime.now(ZoneInfo("America/New_York"))).total_seconds()`
   - Logs the next run time
   - Sleeps until then (with CancelledError handling)
   - Checks budget_guard.can_start_run() (same as existing loop)
   - Executes agent via `AgentExecutor(agent).execute()`
   - After successful execution, calls `await self._push_agent_output(agent, result)` if agent output exists
   - Emits events via `emit_agent_events()` with `pushed_to_channel='telegram'` if push succeeded, else without it
   - Loops back to recalculate next_run (prevents drift -- Research Pitfall 1)

3. **Add `_push_agent_output()` async method** that pushes agent output directly to Telegram. Logic:
   - Read `TELEGRAM_BOT_TOKEN` and `TELEGRAM_WHITELIST` from env
   - If either missing, log and return False
   - Get chat_id from first whitelist entry
   - Format message: "Good morning. Here's your briefing:\n\n" prefix for morning-briefing, "Evening digest:\n\n" prefix for evening-digest, no prefix for others
   - Use `from aiogram import Bot` to create a Bot instance, send message (split at 4096 chars using same splitting logic as TelegramChannel -- for simplicity, just truncate at 4096 or use `bot.send_message` which auto-handles), close session
   - Return True on success, False on failure
   - This push bypasses the rate limiter (Research Pitfall 5: scheduled pushes should not be rate-limited)

4. **Modify `start()` method** to branch on `agent.schedule`:
   - If `agent.schedule` is not None and not empty, create task with `_run_scheduled_agent(agent)` and log the schedule
   - Otherwise, use existing `_run_agent_loop(agent)` (backward compatible)

Import additions at top: `from zoneinfo import ZoneInfo` and `from datetime import time` (time class for comparisons).

Do NOT modify `_run_agent_loop()` -- it stays as-is for interval-based agents (email-triage).
