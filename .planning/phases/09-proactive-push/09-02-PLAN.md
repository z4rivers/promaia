**1. Add daily cap and cross-channel dedup to RateLimiter in rate_limiter.py:**

a) Add `self.max_per_day = 10` to `__init__()`.

b) Add a `_check_daily_cap(self) -> bool` method:
   ```python
   def _check_daily_cap(self) -> bool:
       """Check if daily notification cap has been reached across all channels."""
       db = get_postgres_db()
       row = db.fetch_one(
           "SELECT COUNT(DISTINCT id) AS cnt FROM brain.events "
           "WHERE routed_at IS NOT NULL "
           "AND routed_at::date = CURRENT_DATE "
           "AND urgency != 'archive'",
       )
       daily_count = row["cnt"] if row else 0
       if daily_count >= self.max_per_day:
           logger.info(f"Rate limit: daily cap reached ({daily_count}/{self.max_per_day})")
           return False
       return True
   ```

c) In `allow()`, add daily cap check right after the interrupt bypass (after `if urgency == "interrupt": return True`). Call `if not self._check_daily_cap(): return False`.

d) Modify the hourly cap query for cross-channel dedup. Change from:
   ```sql
   SELECT COUNT(*) AS cnt FROM brain.events
   WHERE routed_at IS NOT NULL AND channel = %s
   AND routed_at > NOW() - INTERVAL '1 hour'
   ```
   To:
   ```sql
   SELECT COUNT(DISTINCT id) AS cnt FROM brain.events
   WHERE routed_at IS NOT NULL
   AND routed_at > NOW() - INTERVAL '1 hour'
   AND urgency != 'archive'
   ```
   Remove the `channel = %s` parameter binding since we're counting across all channels now. This prevents a single event delivered to both dashboard and telegram from counting as 2 against the hourly cap.

**2. Update promaia.config.json:** Set email-triage `"interval_minutes": 10` (was 480). This reduces urgent email detection latency from 8 hours to ~10 minutes. At $0.004/run, 144 runs/day = $0.58/day = $17.40/month. The event router polls every 30s, so once an interrupt event is emitted, Telegram delivery happens within 30s. Total worst-case latency: ~10.5 minutes.

Note: The PUSH-06 requirement says "within 1 minute." True 1-minute latency requires either Gmail push notifications or a direct Gmail API check loop (future enhancement). The 10-minute interval is a practical compromise that represents a massive improvement from 480 minutes. Add a code comment in the config or scheduler noting this tradeoff.

Create a reply handler that intercepts inline replies to pushed notifications. The handler:
- Uses an aiogram Router with a filter: `lambda msg: msg.reply_to_message is not None and msg.reply_to_message.from_user and msg.reply_to_message.from_user.is_bot`
- In the handler function, checks if the original message is a push notification by matching prefixes: "URGENT:" (from TelegramChannel.deliver()), "Good morning." (from _push_agent_output()), or "Evening digest:" (from _push_agent_output())

- For briefing replies: captures "Reply to morning briefing:\n\n{reply_text}" with domain="working"
- For digest replies: captures "Reply to evening digest:\n\n{reply_text}" with domain="working"
- Uses `capture_memory()` from `promaia.telegram.brain_ops`
