  <action>
    Create `promaia/telegram/` package with these three utility modules:

    **auth.py** -- WhitelistMiddleware (aiogram BaseMiddleware):
    - Load allowed chat IDs from `TELEGRAM_WHITELIST` env var (comma-separated integers)
    - In `__call__`, check `event.chat.id` against the whitelist set
    - Non-matching messages: return immediately (silent drop, no response, no error log) -- TELE-02
    - Matching messages: call `await handler(event, data)` to proceed -- TELE-01

    **brain_ops.py** -- Extract brain operations from mcp_server.py as plain async functions returning strings (NOT TextContent objects). Each function wraps libSQL/MuninnDB calls in `asyncio.to_thread()` since psycopg2 is synchronous:
    - `get_briefing() -> str` -- Same SQL queries as `_handle_briefing()` in mcp_server.py (stale projects, pending actions, heartbeat activity). Skip the interview/profile section (not relevant for Telegram). Skip the briefing event log (that is for MCP sessions).
    - `capture_memory(content: str, domain: str | None = None) -> str` -- Same logic as `_handle_capture()`: insert to brain.memories, generate embedding via VectorDBManager, extract actions via extract_actions(). Return "Captured." or "Captured. Extracted N action(s)." Skip MuninnDB dual-write (non-essential for mobile capture).
    - `search_brain(query: str, limit: int = 5) -> str` -- Same logic as `_handle_search()`: generate query embedding, pgvector cosine distance search. Format results as numbered list with domain labels and similarity scores. Skip MuninnDB activate (simplify for mobile).
    - `get_actions(status: str = "pending") -> str` -- Same SQL as `_handle_actions()` list path: query brain.actions with LEFT JOIN domains, format as numbered list.
    - `get_projects() -> str` -- Query brain.contexts joined with brain.domains, format as a list showing project name, priority, staleness, and current state. This maps to the stale projects section of briefing but shows ALL projects, not just stale ones.

    Use `from promaia.storage.postgres_db import get_postgres_db` for all DB access. Use `from promaia.storage.vector_db import VectorDBManager` for embedding generation in capture and search. Use `from promaia.brain.extraction import extract_actions` for action extraction. Wrap all synchronous DB calls in `asyncio.to_thread()` to avoid blocking the event loop.

    **formatting.py** -- Message splitting utility:
    - `send_long_message(message: Message, text: str)` -- async function that splits text over 4096 chars at paragraph boundaries, falling back to line boundaries. Adapt the `_split_message()` pattern from `promaia/discord_bot/bot.py` but use 4096 as the limit (Telegram's max) instead of 2000 (Discord's max).
    - `_split_message(text: str, max_length: int = 4096) -> list[str]` -- Internal splitting logic.

    **__init__.py** -- Empty init file for the package.

    - `/briefing` -- Call `get_briefing()`, send via `send_long_message()` -- TELE-03
    - `/search <query>` -- Extract query text after `/search`, call `search_brain(query)`, send result. Show usage hint if no query provided -- TELE-04
    - `/capture <text>` -- Extract text after `/capture`, call `capture_memory(content)`, reply with result. Show usage hint if empty -- TELE-04
    - `/projects` -- Call `get_projects()`, send via `send_long_message()` -- TELE-04
    - `/actions` -- Call `get_actions()`, send via `send_long_message()` -- TELE-04
    - Use `from aiogram.filters import Command` for command matching
    - Use `from aiogram import Router` -- create module-level `router = Router()`

    **handlers/messages.py** -- Free-text catch-all handler:
    - Register with `@router.message()` (no filter -- catches everything not caught by commands or voice)
    - For each incoming text message: detect domain via `engine.detect_mode(message.text)`, call `capture_memory(message.text, domain=detected_domain)`, reply with the capture confirmation -- TELE-05
    - Import `from promaia.brain.engine import detect_mode`
    - The mode returned by detect_mode maps to domain: working->work, planning->planning, capturing->capture, reviewing->review. Or just pass the mode name directly as the domain string.

    **handlers/__init__.py** -- Empty init.

    **bot.py** -- Main bot module:
    - `start_bot()` async function that:
      1. Reads `TELEGRAM_BOT_TOKEN` from env. If missing, log error and exit.
      2. Creates `Bot(token=token)`
      3. Creates `Dispatcher()`
      4. Registers `WhitelistMiddleware` on `dp.message.middleware()`
      5. Includes routers in order: `commands.router` FIRST, `messages.router` LAST (catch-all must be last to avoid intercepting commands)
      6. Calls `dp.start_polling(bot, backoff_config=BackoffConfig(min_delay=1.0, max_delay=30.0, factor=1.5, jitter=0.1), polling_timeout=30)` -- TELE-08
    - Import BackoffConfig from `aiogram.utils.backoff` (verify actual import path -- it may be `aiogram.dispatcher.backoff` or a direct parameter; check aiogram 3.26 docs. If BackoffConfig is not importable, the backoff behavior is built into start_polling by default -- just use `polling_timeout=30`).
