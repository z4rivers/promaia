<task type="auto">
  <name>Task 2: Create brain MCP server with 7 tools</name>
  <files>promaia/brain/mcp_server.py</files>
  <action>
Create `promaia/brain/mcp_server.py` using the low-level `mcp` SDK pattern (matching `promaia/mcp/gmail_tools_server.py`).

1. Server setup:
   ```python
   import asyncio, logging, os, uuid, json
   from mcp.server import Server
   from mcp.server.stdio import stdio_server
   from mcp.types import Tool, TextContent
   from promaia.storage.postgres_db import get_postgres_db
   from promaia.brain import engine
   from promaia.brain.extraction import extract_actions
   ```
   Generate a session UUID at module level: `SESSION_ID = str(uuid.uuid4())`

2. Register 7 tools via `@server.list_tools()`:

   **briefing** — No required params. Returns stale projects (query brain.contexts JOIN brain.domains WHERE NOW() - last_updated > stale_threshold_days * INTERVAL '1 day'), pending actions (brain.actions WHERE status='pending', LIMIT 10), recent heartbeat activity (brain.events WHERE source='heartbeat' AND created_at > NOW() - INTERVAL '24 hours'). Log a 'briefing' event to brain.events. Format output as concise text.

   **capture** — Required: content (string). Optional: domain (string). Insert row into brain.memories with content, domain, source='session', source_id=SESSION_ID. After insert, generate embedding async: use VectorDBManager.generate_embedding(content), then UPDATE brain.memories SET embedding = %s WHERE id = %s. Call extract_actions(content) — if has_actions, insert each into brain.actions with the memory_id. Log 'capture' event. Return brief confirmation: "Captured." or "Captured. Extracted N action(s)."

   **search** — Required: query (string). Optional: limit (int, default 10). Generate query embedding via VectorDBManager.generate_embedding(query). Query brain.memories with `embedding <=> %s::vector AS distance ORDER BY distance LIMIT %s`. Must call `register_vector(conn)` on the connection before the query (PITFALL from research). Return formatted results.

   **recall** — Optional: domain (string), days (int, default 30), limit (int, default 20). Query brain.memories filtered by domain (if provided) and created_at > NOW() - days * INTERVAL '1 day'. Order by created_at DESC. Return formatted results.

   **context** — Required: domain (string). Query brain.contexts JOIN brain.domains WHERE domains.name = domain. Return directive, current_state, last_updated, priority, stale_threshold_days. If not found, return "No context found for domain: {domain}".

   **update_context** — Required: domain (string). Optional: directive (string), current_state (string), priority (int). UPDATE brain.contexts SET the provided fields, plus last_updated = NOW(), WHERE domain_id = (SELECT id FROM brain.domains WHERE name = domain). If no context row exists, INSERT one (upsert pattern). Log 'context_update' event. Return brief confirmation.

   **actions** — Optional: status (string, default 'pending'), domain (string), mark_done (int — action ID to mark as done). If mark_done provided, UPDATE brain.actions SET status='done', completed_at=NOW() WHERE id=mark_done. Otherwise, SELECT from brain.actions filtered by status and domain. Return formatted list.

3. `@server.call_tool()` dispatcher routes to handler functions by tool name.

4. Main entry point:
   ```python
   async def main():
       logging.basicConfig(level=logging.INFO, stream=__import__('sys').stderr)
       async with stdio_server() as (read_stream, write_stream):
           await server.run(read_stream, write_stream, server.create_initialization_options())

   if __name__ == "__main__":
       asyncio.run(main())
   ```

PITFALLS to avoid:
- Call `register_vector(conn)` before ANY query that touches the embedding column (search, capture with embedding update).
- Use `psycopg2.extras.RealDictCursor` for queries that return named fields.
- Embedding generation in capture: insert the memory row first WITHOUT embedding, return the confirmation immediately, then update the embedding. Use `asyncio.create_task()` to generate and update embedding after the response is sent, OR do it synchronously since the MCP call is already async. For Phase 2 simplicity, synchronous is fine (200-500ms acceptable).
- Session briefing idempotency: check brain.events for an existing 'briefing' event with today's session_id. If found, still return the briefing data but skip logging a duplicate event.
