❯ what are performance implications of local or VPS?

● Good question. Let me break it down practically:

  Your database (Supabase) is in the cloud regardless. So the MCP server is always making network calls to Supabase — the question is just where the MCP server sits.

  Local (PC + ngrok):
  - Claude Code on PC: MCP server is localhost → instant to reach, then one network hop to Supabase. Fast.
  - iPhone via claude.ai: Request path is iPhone → claude.ai → ngrok servers → your PC → Supabase. 3+ hops. ngrok free tier adds ~100-200ms latency. Paid ngrok is faster.
  - Downside: PC must be on. But your heartbeat agent also needs the PC on overnight, so this is already a requirement.

  VPS ($5/mo — Railway, Render, etc.):
  - Claude Code on PC: MCP calls go over the internet to the VPS → adds ~20-50ms per call. Slightly slower for PC usage.
  - iPhone via claude.ai: iPhone → claude.ai → VPS → Supabase. Direct, no ngrok middleman. Faster and more reliable from phone.
  - Upside: Always on, no dependency on your PC being awake.

  The practical reality:
  - Your heartbeat needs the PC running anyway → PC is already on overnight
  - If PC is on, ngrok is on → iPhone access works
  - The only time VPS helps is when your PC is genuinely off and you want to capture thoughts from your phone

  Performance difference is small. Both paths hit Supabase over the internet. The real difference is availability (always-on vs PC-dependent) not speed.
