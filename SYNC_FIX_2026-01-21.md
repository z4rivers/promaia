# Sync Fixes - January 21, 2026

## Issues Fixed

### 1. Gmail Authentication Blocking Sync
**Problem:** When Gmail tokens expired, the sync would stop and prompt for interactive authentication, blocking all other databases from syncing.

**Solution:** 
- Modified Gmail connector to not prompt for interactive authentication during automated syncs
- Failed Gmail syncs now return proper error results instead of blocking
- Other databases continue syncing even if Gmail authentication fails
- Clear error messages with instructions on how to fix authentication

### 2. No Sync Completion Notifications
**Problem:** No feedback when syncs complete successfully, making it hard to know when sync jobs finish.

**Solution:**
- Added macOS system notifications for sync completion
- Success notifications show number of databases synced and duration
- Failure notifications indicate how many databases failed
- Notifications use appropriate system sounds (pleasant for success, alert for failures)

## About the "No entries found in registry" Warnings

You mentioned seeing these warnings:
```
No entries found in registry for koii.journal (database_id: 259700448ad145849e67fa1040a0e120)
No entries found in registry for koii.anglds (database_id: 1463083699334549557)
No entries found in registry for koii.ds (database_id: 1291943271509135412)
```

**These are NOT sync failures** - they only appear when using the `-b` (browse) mode with databases that haven't had content loaded yet. The browse mode checks the registry to see what's available to load into context.

**What this means:**
- The databases are configured correctly
- Syncs ARE working for these databases
- The registry just doesn't have entries loaded yet (first sync, or empty database)

**To populate the registry:**
Run a full sync and then use the databases normally:
```bash
maia sync
maia chat -sql "recent activity" -b koii
```

After the first sync, the registry will be populated and these warnings will disappear.
